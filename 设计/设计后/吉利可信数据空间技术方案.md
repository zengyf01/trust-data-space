## 一、项目概述

### 1.1 项目背景

吉利控股集团需要建设可信数据空间产品，实现数据要素的安全流通和可信交换。根据数标委《可信数据空间 能力建设要求》及吉利公司技术协议，设计本技术方案。

### 1.2 建设目标

1. **数据安全流通**：实现数据可用不可见、可信数据交换
2. **隐私计算能力**：支持多方安全计算、联邦学习
3. **安全沙盒环境**：提供可信的执行环境保护敏感算法和数据
4. **区块链存证**：关键操作上链存证，保证不可篡改
5. **3000并发支持**：满足大规模并发访问需求

### 1.3 设计依据

| 标准/需求 | 说明 |
|----------|------|
| 《可信数据空间 能力建设要求》 | 数标委国家标准 |
| 《可信数据空间 技术架构+数字合约》 | 数标委技术标准 |
| 吉利技术协议 | 0512版本 |
| 吉利技术评分标准 | 控股数智化 |

## 三、模块详细设计

### 3.1 服务平台 (TDS)

#### 3.1.1 模块职责

| 模块 | 功能 | 核心服务 |
|------|------|----------|
| **数字合约** | 合约全生命周期管理 | 创建、签署(双签)、执行、终止 |
| **数据目录** | 数据产品元数据管理 | 注册、发布、查询、审核 |
| **认证鉴权** | 参与方身份认证 | 注册、认证、API签名验证 |
| **运营管理** | 租户运营控制 | 租户管理、角色权限、资源分配 |
| **审计存证** | 操作日志存证 | 证据上链、区块链查询、合规报告 |

#### 3.1.2 核心服务

```
TDS核心服务:
├── tbContractManage         # 数字合约管理
│   ├── create()           # 创建合约
│   ├── signContract()     # 双签签署
│   └── execute()         # 合约执行
├── evidenceLog            # 存证服务
│   ├── record()          # 记录存证
│   └── query()           # 链上查询
├── connectorManage        # 连接器管理
│   ├── register()        # 连接器注册
│   └── heartbeat()       # 心跳检测
└── operationLog          # 运营日志
    ├── optLogSync()      # 日志同步
    └── dataConsumption() # 数据消费日志
```

#### 3.1.3 核心流程

**数字合约签署流程:**
```
1. 需方创建数据服务工单
2. 供方确认并创建数字合约
3. 供方首次签名 (Provider Sign)
4. 需方二次签名 (Consumer Sign)
5. 合约生效 (EXECUTING)
6. 执行数据交付
7. 记录交付存证 (EvidenceLog)
```

### 3.3 连接器 (Datar)

#### 3.3.1 模块职责

| 模块 | 功能 | 说明 |
|------|------|------|
| **数据连接器** | 内部数据源对接 | MySQL、PostgreSQL、SFTP、HTTP |

```

    → API放行
```

### 8.2 认证流程

```
远程认证流程:
1. TEE内部Attestation Agent生成证据
2. KBS接收并转发给Attestation Service
3. Attestation Service验证证据
4. RVPS提供参考值校验
5. 验证通过后释放密钥
6. 建立可信通信通道
```
