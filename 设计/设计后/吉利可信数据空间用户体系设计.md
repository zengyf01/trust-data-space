## 一、概述

### 1.1 设计背景

吉利可信数据空间涉及三个核心平台：
- **服务平台 (TDS)**：管理数据空间、机构、连接器、合约
- **交付平台 (DOS)**：管理工单、沙盒、隐私计算作业
- **连接器 (Datar)**：部署在客户机房，管理数据源

**核心问题：** 连接器可能部署在客户机房，其用户体系可能与服务平台不在一起。

### 1.2 设计目标

| 目标 | 说明 |
|------|------|
| **统一管理** | 平台用户统一管理，简化运维 |
| **独立运行** | 连接器可独立运行，不依赖中心平台 |
| **灵活切换** | 支持集中式和分布式两种部署形态 |
| **安全合规** | 符合国密SM2签名认证要求 |

### 3.2 用户类型

| 用户类型 | 所属平台 | 说明 |
|----------|----------|------|
| **机构管理员** | TDS | 管理整个机构，创建连接器，审核用户 |
| **普通用户** | TDS | 使用数据服务，参与合约 |
| **数据管理员** | Datar | 管理本地数据源，发布数据产品 |
| **算法工程师** | Datar | 使用安全沙盒，进行隐私计算 |
| **访客** | Datar | 查看数据目录，不进行操作 |

## 五、认证流程设计

### 5.1 统一部署认证流程

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                        统一部署认证流程                                            │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                 │
│  用户                      中心平台                      认证流程                  │
│  ───                      ────────                      ──────                  │
│                                                                                 │
│  1. 登录请求 ──────────▶ MaxKey SSO                                           │
│                              │                                                  │
│                              ▼                                                  │
│  2. 输入账号密码 ────▶ MaxKey ──▶ 验证账号密码                                   │
│                              │                                                  │
│                              ▼                                                  │
│  3. 生成Token ───────▶ MaxKey ──▶ 创建会话 ──▶ 返回Token                        │
│                              │                                                  │
│                              ▼                                                  │
│  4. 带Token访问 ◀───────────────────▶ API请求                                  │
│                              │                                                  │
│                              ▼                                                  │
│  5. 验证Token ◀──────────────▶ 验证 ──▶ 返回数据                                 │
│                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────┘
```

**认证接口：**
```
POST /api/maxkey/login
Request: { account, password }
Response: { token, tokenType, expiresIn, userId, maxKeyToken, systemToken }

POST /api/maxkey/logout
Header: Authorization: Bearer {token}
Response: { code: 200 }
```

### 5.3 API签名认证流程

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                        SM2签名认证流程                                          │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                 │
│  签名原文: appId + timestamp + requestBody                                      │
│                                                                                 │
│  1. 拼接签名原文                                                                │
│     plainText = "appId" + "timestamp" + "{\"key\":\"value\"}"                   │
│                                                                                 │
│  2. SM2私钥签名                                                                 │
│     signature = SM2Sign(privateKey, plainText)                                  │
│                                                                                 │
│  3. 添加HTTP Header                                                             │
```

## 九、部署配置

### 9.1 统一部署配置

```yaml
# application.yml (TDS/DOS)
tds:
  auth:
    mode: unified              # 统一用户模式
    sso:
      enabled: true
      provider: maxkey
      issuer: http://maxkey.geely.com
    sm2:
      enabled: true
      sign验证: true
```

### 9.2 分布式本地配置

```yaml
# application.yml (Datar - 分布式)
datar:
  auth:
    mode: local                # 本地用户模式
    local:
      enabled: true
      encryption: sm2
    unified:
      enabled: false           # 不使用统一用户
```

### 9.3 混合模式配置

```yaml
# application.yml (Datar - 混合模式)
datar:
  auth:
    mode: local                # 本地用户优先
    local:
      enabled: true
    unified:
      enabled: true            # 也支持统一用户访问
      fallback: true           # 本地用户不可用时切换
```

## 十、总结

### 10.1 设计要点

| 要点 | 说明 |
|------|------|
| **双模式支持** | 统一部署和分布式部署均可支持 |
| **灵活切换** | 通过配置切换用户模式 |
| **本地独立** | 连接器可离线独立运行 |
| **统一管理** | 中心平台可管理所有连接器用户 |
| **安全认证** | 国密SM2签名保障API安全 |

### 10.2 部署建议

| 场景 | 推荐模式 | 说明 |
|------|----------|------|
| 吉利内网部署 | 统一部署 | 用户体系在一起，简化管理 |
| 客户机房部署 | 分布式本地 | 连接器独立运行，本地用户管理 |
| 合作伙伴接入 | 分布式统一 | 使用平台用户，通过凭证访问 |
| 离线测试环境 | 分布式本地 | 无网络情况下本地用户认证 |
